1. **Reliability / SACK:** `V02_SACK_OFF_4M` vs `V01_BASELINE_4M`
2. **BDP buffers:** `V01_BASELINE_4M` vs `V03_BUF_16M` vs `V04_BUF_64M`
3. **Congestion control:** `V05_CUBIC_FQ_16M` vs `V06_BBR_FQ_16M`
4. **Encryption:** `V03_BUF_16M` vs `V08_CIPHER_CHACHA_16M`
5. **Data reduction:** `V09_COMP_RAW_16M` vs `V10_COMP_GZIP_16M`

## Experimental Design

This benchmark uses a randomized complete-block design to evaluate
endpoint-level optimization strategies for large data transfers over
long-distance cloud paths.

Each route is evaluated using:

- 30 randomized complete blocks
- 9 experimental conditions per block
- A 10 GiB logical payload per transfer
- 270 executions per completed route campaign

The experimental design covers six cloud routes:

- DAL-WDC
- DAL-LON
- DAL-SYD
- WDC-LON
- WDC-SYD
- LON-SYD

The complete design therefore comprises 1,620  executions
across 180 randomized blocks.

The primary research question is whether transport- and
operating-system-level controls can improve large data transfers when
application behavior cannot be modified. This scenario is relevant to
enterprise workloads in which replication is performed by integrated
application mechanisms and intervention is primarily possible at the
transport, network, or operating-system level.

Application-level compression is included as a separate data-reduction
reference. It is not treated as a TCP optimization because it changes
the amount of data that must be transmitted.

## Raw Experimental Evidence

The original output of each experimental campaign is preserved under
`data/raw/`.

Each route campaign is maintained as an independent directory:

data/raw/
├── DAL-WDC/
├── DAL-LON/
├── DAL-SYD/
├── WDC-LON/
├── WDC-SYD/
└── LON-SYD/

Depending on the campaign output, each directory contains the original
artifacts generated by the experimental framework, including:

- `campaign_audit.json`
- `execution_plan_sha256.txt`
- `execution_plan.json`
- `iterations.csv`
- `observed_receiver_state.json`
- `observed_sender_state.json`
- `paired_inference.csv`
- `report.md`
- `restoration_report.json`
- `summary.csv`

`iterations.csv` is the authoritative execution-level dataset used to
regenerate the statistical analysis.

The accompanying campaign artifacts preserve information required to
audit the execution plan, experimental environment, observed endpoint
state, validation results, and campaign-level outputs.

Files under `data/raw/` are treated as immutable experimental evidence.
They must not be manually corrected or edited. Any normalization,
correction, exclusion, or transformation required for analysis is
performed as a documented processing step outside the raw dataset.

Spreadsheet files used for exploratory inspection are derivative
representations of `iterations.csv` and are not authoritative inputs
to the reproducible analysis pipeline.

Before public release, campaign artifacts should be reviewed for
credentials, tokens, account identifiers, host information, or other
environment-specific information that should not be publicly
disclosed.

## Measurement Definitions

### Application Goodput

Application goodput represents the effective rate at which the
application payload is completed at the destination.

For uncompressed conditions, goodput is derived from the logical
payload size and normalized transfer duration.

### Logical Goodput

For data-reduction experiments, this benchmark distinguishes logical
goodput from network throughput.

Logical goodput is calculated as:

Logical goodput = original logical payload size / total transfer time

For the Gzip condition, the original uncompressed payload size is used
in this calculation.

Logical goodput therefore represents the effective rate at which the
original information becomes available at the destination after
decompression.

It must not be interpreted as the throughput of the compressed bytes
over the network or as an increase in TCP path capacity.

This distinction is particularly important when comparing
`V10_COMP_GZIP_16M` against `V09_COMP_RAW_16M`: compression reduces the
amount of data that must cross the network, whereas the primary
transport and operating-system treatments attempt to transfer the same
payload more efficiently.

## Reproducibility requirements

Each run should preserve the configuration, randomization seed, source and destination environment, kernel and OpenSSH versions, route label, payload characteristics, elapsed-time unit, integrity status, and telemetry fields defined in `docs/data-dictionary.md`. Raw data should never be manually edited; corrections should be implemented as a documented processing step.


## Reproducing the Manuscript Results

The manuscript results are designed to be reproducible from the
original campaign outputs rather than from manually prepared
spreadsheets.

The reproducibility chain is:

experimental configuration
    ↓
randomized execution plan
    ↓
route campaign
    ↓
iterations.csv
    ↓
documented normalization
    ↓
block-matched statistical analysis
    ↓
processed results
    ↓
publication tables and figures

The primary comparisons are:

- `V02_SACK_OFF_4M` vs `V01_BASELINE_4M`
  - SACK disabled vs enabled

- `V03_BUF_16M` vs `V01_BASELINE_4M`
  - 16 MiB vs 4 MiB buffer ceiling

- `V04_BUF_64M` vs `V03_BUF_16M`
  - 64 MiB vs 16 MiB buffer ceiling

- `V06_BBR_FQ_16M` vs `V05_CUBIC_FQ_16M`
  - BBR/fq vs CUBIC/fq

- `V08_CIPHER_CHACHA_16M` vs `V03_BUF_16M`
  - ChaCha20-Poly1305 vs AES-GCM under the corresponding transport
    condition

The manuscript summarizes the primary treatment effects using:

- Block-matched percentage effect
- 95% confidence interval
- Holm-adjusted p-value

The comparison between `V10_COMP_GZIP_16M` and
`V09_COMP_RAW_16M` is analyzed separately because compression changes
the amount of data transmitted and therefore answers a different
operational question from the primary endpoint treatments.

Additional statistical diagnostics and sensitivity analyses may be
retained as reproducibility artifacts without being presented as
primary outcomes in the manuscript.

Processed datasets, statistical outputs, and publication figures must
be generated from the preserved campaign data through documented and
repeatable processing steps. Manual modifications to raw experimental
measurements must not be introduced into the analysis pipeline.
